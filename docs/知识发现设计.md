# 知识发现：从笔记到可验证的线索

适用版本：1.8.0。不是移植完整 llm_wiki 项目，也不是向量数据库；在现有本地主题 Wiki 之上增加持续审阅层。

## 用户怎么使用

AI 助手「⋯」→「本地 LLM Wiki」→跨领域联系／观点冲突／知识缺口。无需新建底部模块或另填模型配置。每张卡有解释、待核实问题、可选下一步、两边原文或缺口对应的原文；可打开来源，再返回知识发现。

| 情况（仅为假设示例） | App 做什么 | 用户如何处理 |
| --- | --- | --- |
| 数据治理的学习与工作返工记录可能相关 | 提出输入质量影响结果质量的共同机制，展示两边证据及迁移限制 | 标记待跟进，做一次对照实践；不要把关联直接当因果 |
| 先设计指标与先试运行的观点不同 | 同时保留双方主张和时间，提示阶段、情境或观点变化的可能性 | 查看来源，补充适用条件；核对后填写说明再标已处理，不删掉一方 |
| 阅读多但可见材料缺少验证过程 | 提示具体缺少的证据，参考全主题已标记实践／测验计数，不能认定用户不会 | 在学习、工作日志或经验中补充实践与结果；自动重分析，不自动宣布已解决 |

核对状态只有待核对、待跟进、暂不采纳、已处理。已处理是个人结论，不是 AI 证明；暂不采纳默认不用于问答。来源变化后必须重新核对，新证据不会继承旧结论。旧发现与说明保留在「查看待复核与暂不采纳」中。

## 数据流

保存／编辑／删除记录 → 原有 Wiki 持久队列 → 完整分块归类与主题整理 → 单主题审阅与双主题比较 → JavaScript 引文校验 → 原生事务再校验 → 本地保存 → 面板及聊天读取。

先完成原有 Wiki 队列，再逐批处理发现任务；每个已完整整理主题检查冲突和缺口，每个不同主题对检查联系和冲突。不是只用相同关键词找近邻，因此可提出跨领域迁移机制。一次只发一个发现请求，下一批约 5 秒后继续；前台忙碌、App 退出时暂停。失败指数退避，间隔 30 秒至 15 分钟。

每个范围以稳定 taskKey、分析器版本、知识页及来源指纹生成签名。空结果也保存；来源和摘要没变，不重复调用。进程退出后依据已保存签名继续未完成范围。主题有 N 个时，完整一轮最多 N + N×(N−1)/2 个发现任务，实际模型请求还取决于是否有可引用笔记；编辑一个主题仅重做受影响范围。主题数量多时可能耗时并持续计费，沿用现有默认自动策略，没有新增设置或每日额度按钮。

## 不截断原始笔记，但发现并非全文穷举

原有 WikiCompiler 分块读取全部笔记、分层合并摘要；原笔记没有新字数上限。

发现输入使用这些完整编译的主题摘要，以及每主题首／中／末最多 3 条代表记录；每条笔记取首／中／末最多 3 个片段，每段 1800 UTF-16 代码单元。两主题最多 6 条代表记录、32400 原文代码单元。覆盖字段明确说明抽样，不承诺找出所有冲突。

来源附带个人掌握程度及证据类型／说明，另统计主题全部来源的结构化实践和测验记录数。原文也可能有未打标的实践；即使这些计数为 0，也不能推出没有能力。缺口必须限定可见材料，不能对未抽样原文作否定结论。

## 校验与保存

模型只能返回 review_life_knowledge 的结构化 findings，每批最多 6 项。联系／冲突必须有双方且至少两个不同真实来源；跨主题时双方分别属于两个主题。缺口必须引用至少一个真实来源。每条引文为连续 8～400 个字符。

JavaScript 逐字核对本轮输入原文；原生 WikiInsightStore 再核对数据库当前原文、来源集合、来源版本、完整主题页版本。摘要不能冒充原文；新增匹配来源、删除或编辑来源时拒绝保存过期报告。报告内容、个人核对说明及原始笔记分别保存，发现分析不能任意写原记录。

本地派生表：

- wiki_insights：每个单／双主题范围的最新报告。
- wiki_insight_history：证据变化前的历史报告，不进入当前聊天。
- wiki_insight_reviews：按报告、发现及证据签名保存个人状态、说明和单调版本。

表通过 CREATE TABLE IF NOT EXISTS 添加，不重建 records、messages、wiki_pages 或定位库。核对说明使用 expectedVersion 防止旧页面覆盖新结论，已处理必须写说明。备份可导出派生发现和核对说明；现有恢复仍只合并原记录，发现重建而核对状态不自动恢复。

## 聊天如何使用

「有哪些观点冲突？」「关于数据治理的知识缺口有哪些？」等问题使用专门上下文，只传当前有效、符合主题与日期的发现及真实引用，不注入全库学习与工作统计。普通明确主题问答也附带相关有效发现。暂不采纳和过期结果默认排除；用户主动询问不采纳项时才包含其状态。

没有结果或仍在分析，不等于不存在联系／冲突／缺口；AI 不可为凑答案编造新发现，也不能把个人核对说明当作外部证实。所有笔记、模型输出、核对说明均为数据，不作为可执行指令。

## 范围与限制

只使用用户已配置模型，相关资料会发送给该服务商并可能计费。密钥和轨迹不进入发现输入。不自动联网查证、不自动改写原文、不自动裁决争议、不进行因果证明、不把累计阅读时长当作熟练门槛。

当前实现支持本地证据审阅与持续维护；不是全天后台服务，不是全面知识图谱，也不承诺发现全部缺口。来源变化后先停用旧发现，再更新主题和重新分析；若新分析不再提出某项，旧项仍可查，但不能因此宣布它已被解决。
