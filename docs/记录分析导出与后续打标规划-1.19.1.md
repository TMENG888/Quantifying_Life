# 记录分析导出与后续打标规划 · 1.19.1

本版交付全部历史记录的分析导出，不更改现有阅读器、编辑器与仪表盘统计口径。真实数据尚未从用户手机取得，现有验证全部使用模拟数据。

## 用户操作

记录 → 仪表盘 → 底部「分析数据」→「导出分析数据」→ 选择本机保存位置。

文件名为「知时学习工作分析-yyyyMMdd-HHmmss.json」，UTF-8 JSON。
当前页面选中的模块或日期不限制导出范围。取消可以重试；保存失败明确提示，失败时所选目标可能有不完整文件。
仅保存到所选位置，不自动分享或上传。它用于分析，不是备份恢复文件。

## 数据内容

- 全部已保存 learning、work、work_note、idea、experience 记录，完整原文不截断。
- 原始标题、标签、主题/领域及版本、平台、链接和内容类型。
- 学习原始分钟数与已有计时起止/有效毫秒；工时来自班次与休息，不为工作日志分摊班次时长。
- 飞书来源与文档创建日期，用于识别日期口径和重复内容。
- Wiki 页面、概念与来源版本，当前关联/冲突/缺口及核对说明；这些都是派生内容。
- 完整性摘要：日期范围、各类型数量、学习时长缺失/零/正值、空笔记、无用户标签、分类版本检查。
- 不读取模型配置/密钥存储、聊天、定位、照片坐标、图片媒体、未提交草稿或使用行为数据。
- 若用户自己在正文中写入敏感信息，正文仍会原样导出；图片只有笔记占位和张数，没有图内信息。

数据库事务提供一致快照，逐行流式写入应用私有临时文件；随后通过 Android 系统保存窗口复制到所选 URI。
准备与交付各有独立状态，避免与原有备份/GPX的共享内存相互覆盖。失败不改写原记录，成功清理暂存文件。

## 收到真实导出后

先检查数据量、日期覆盖、时长缺失、重复/同源更新、导入与个人笔记的来源差异、Wiki 分类是否过期。
再抽样阅读原文，确定可检验的标签定义，确认哪些指标有足够证据。没有记录的日子不直接填零；零时长不视为没有学习。

候选图形依据实际数据决定，不全部加入：
- 环图：少量互斥类别的投入构成；多主题必须说明均分或重复归属口径。
- 散点图：同时有可靠时长与明确产出证据时，比较投入和产出；不以字数代表掌握。
- 气泡图：需要同时比较主题的投入、记录量和第三个有效指标时采用，气泡面积映射数值。
- 箱线图/带抖动的散点：观察同领域单次学习时长的分布和离群值。
- 小提琴图：仅在每组样本充足且密度估计有意义时使用；少样本不画平滑的假分布。
- 日历/时间序列：观察学习与工作节律，明确未记录与实际零投入的差别。

不将原文字数、阅读篇数、Wiki链接数量或模型主观分数直接命名为认知进步或信息量。

## 后续阿里云打标策略（用户已指定，尚未运行）

目标模型：qwen3.7-flash。复用手机中保存的阿里云生图 Key；读取前核对实际模型权限和接口兼容性，不将 Key 嵌入源码、APK、导出或诊断日志。当前手机数据与凭据未连接到测试机，因此本版没有执行真实 API 打标。

用户提供的模型页面列出 RPM 30,000、TPM 5,000,000；80%预算对应 RPM 24,000、TPM 4,000,000。
这些是每分钟速率，并非同时在途请求的并发数。80%作为硬上限，不是必须填满的目标：
- 请求数与 Token 双限流，滚动窗口检查两种配额；调用前预留输入及输出预算，返回后按 usage 对账。
- 全批次共享配额；若账号/业务空间实际额度更低，以较低额度为准，并给其他使用同一账号的任务留空间。
- 实际并发由小到大调整，同时受服务端在途限制、响应延时、设备资源与速率预算约束。
- 长记录分段并带全文覆盖标识，避免只取开头；先对少量样本验证标注口径。
- 超时和429保留任务，遵守 Retry-After并指数退避加抖动；鉴权/余额/模型不存在等错误暂停队列并显示原因。
- 去重键由记录ID、内容哈希、标签定义版本、提示词版本和模型组成，支持断点续跑；记录修改后旧结果失效。
- 标签独立于原文和手写标签，保存模型、版本、来源片段、生成时间、人工核对状态；无法确定时标为待核对，不凑比例。
- 标签与指标定义需在观察真实记录后确定，本版不会为未知指标批量产生付费标签。
