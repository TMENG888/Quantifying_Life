# 轨迹时间定位 · 1.13.0

## 使用

轨迹 → 选择日期 → 地图上方「时间段」或「时刻」。

- 时间段：快速选择 09:00—10:00 等一小时，或编辑开始／结束时间；时间选择完成即更新，也可点「查看轨迹」重试。结束 00:00 表示次日零点，其他跨日范围不支持。包含开始，不包含结束。
- 时刻：输入 09:30，显示前后60秒内最近的可用处理点。标记标注实际采样时刻，状态显示时间差；相同时间差优先较早记录。位置仍受GPS误差与现有平滑／停留估计影响，不是精确历史位置证明。
- 附近没有可用记录：清除旧标记，不跨缺口插值；可主动选择此前或此后的实际记录。待确认的沿用坐标不作为时刻匹配点。
- 全天：恢复完整路线。换日期自动恢复全天；刷新保留当前时间选择。

## 数据与绘制

新增只读 `trackTime`，基于 `TrackStore.day(date, policy, false)`，即整天上下文过滤完成、显示简化之前的数据。不在查询边界重新过滤，不修改数据库或全天过滤参数。

时间段先截取完整处理点，再计算该范围内的参考距离及缺口，最后按既有 TrackDisplay 规则简化绘制。无范围外端点，不跨边界借点。时段内部已有的缺口仍按既有规则画推断虚线，不计距离。读取上限仍为既有120000原始点，超过时明确提示部分数据，不能保证查询完整。

道路匹配路径没有逐顶点时间，不能假装精确裁切。因此仅绘制时间范围完全包含的道路推断；横跨边界的整段道路推断不显示，仍保留时段内的处理轨迹／既有虚线。时刻视图只显示一个位置，不显示全天道路。原始点、GPX、全天距离、采集服务和定位算法均不变；不发送坐标到AI或外部服务，不新增网络权限。

## 交互设计

沿用现有绿色与暖白，不引入新的配色或字体：绿色 #216a54、背景 #f6f5f0、表面 #fff、主文 #1e3029、分隔 #e5e9e0。系统中文字体，时间使用等宽数字。布局为「日期 → 既有地图设置 → 全天/时间段/时刻 → 时间输入 → 地图」，左对齐；时间控制紧邻地图，图面是主角。避免24个小时按钮占屏，使用系统下拉整点时段；输入、按钮不小于48px，错误在原处显示并保留输入。针对既有页面添加局部组件，不重做全局风格。
