# 代码阅读器修复 · 1.15.2

## 原因

原阅读器先按空行拆正文，再分别渲染 Markdown。代码块内部的空行也被拆开，后续片段丢失开头的代码围栏，Python 的 `#` 注释被当作标题，代码与普通段落混排。原有整块 `pre` 配合多列分页，还会让长代码出现过高的容器或大量分页留白。这不是飞书原始代码一定丢失，而是导入后的阅读结构处理错误。

## 改动

- Markdown 分块识别完整围栏，保留源码偏移、空行和缩进；支持反引号及波浪线围栏，短围栏不会提前结束长围栏。
- 代码中的 HTML、Markdown、图片令牌不当作可执行内容、标题或附件解析。
- 代码以绿色／暖纸主题的独立卡片显示；语言和行数可见。长代码在卡片内滚动，不撑高整张阅读页。
- 全屏查看、复制、显示换行。换行仅改变显示，不改写代码。
- 独立代码编辑页；完成后返回记录，最终仍需点击记录保存。修改可撤销／重做。未完成代码修改退出前要求确认。
- 新飞书导入保留原文语言名称；旧记录缺失语言时显示「代码」，不凭空猜测。无需重新导入即可修复旧记录的围栏阅读；此前已损坏或手工删除的内容不能凭显示修复恢复。
- 保留原有左右翻页、保存后进入阅读、首字不裁切的修复。

## 验证原则

使用用户授权的真实代码密集文档，在 Android 15 模拟测试机上核对 21 个代码块与独立飞书读取结果逐字一致，包括空行、缩进、注释和语言字段；不把个人文档 URL 或正文加入仓库测试样本。测试链接通过运行参数传入。

测试覆盖整篇原文编辑往返、一处代码修改不影响其他内容、撤销／重做、原生存储保存与重新打开、嵌套围栏、HTML／图片令牌字面值、全屏换行及返回行为。代码从未执行，不调用付费模型。

同时回归原有图片插入间距、学习日期以及小数列宽翻页。新增卡片按 UI/UX 指引采用有界滚动、48px 操作区域和可见焦点；不是把完整飞书编辑器嵌入 App，也不包含代码执行环境。
