# 1.9.8：停留漂移与状态转换修复

## 原因与实现

问题不仅是卫星误差：旧处理器在移动候选刚出现时就清除了停留锚点，随后撤回短暂候选时没有恢复该状态。最终确认阶段又按每个点不同的误差半径，在原停留点与远端观测之间反复切换，放大了虚线往返。另一个问题是原始回调断开超过五分钟后，即使前后仍是同一片漂移点云，也允许重建远端停留锚点。

- 停留锚点延迟到连续移动确认后释放。确认条件沿用至少三点且跨度四秒，或至少两个可信速度点；并不新增必须有传感器或 Doppler 的条件。候选期继续评估运动，不重复用停留规则否决连贯起步。
- 撤回短候选只回滚到已有停留位置，保留时间和“不确定”标记。最终确认不再用变化的误差半径对任意不确定点逐点吸附。
- 长断采重获位置时还核对断点前后的原始观测位移；同一片点云不因超时而制造位移。不同地点的确实重获仍可建立新停留估计，其间只画推断虚线，不计实测里程。
- 运动采样使用独立回调线程，优先唤醒型线性加速度或加速度传感器，其次才用非唤醒型。连续两次无有效采样窗口后重新注册并尝试去重力的加速度源；最多每三十秒触发一次，非唤醒源只短暂持锁 2.5 秒。陈旧或样本不足的数据仍不是运动证据。诊断新增恢复次数与独立线程字段。

不按地理区域、某天或用户给定的外出时间删除轨迹。原始 SQLite 记录、原始 GPX、D 对照不改写；处理修订号为 10，历史轨迹查看时重新计算，无需重新导入数据。不向第三方发送轨迹。

## 本地数据回放

已对本地历史原始回调回放，检查来源、时间顺序、原始数据不变，以及不确定片段不贡献实测里程。私人数据、具体时段及回放明细不进入源码仓库或 APK。

重点检查了停留时段的虚假反复往返：修复后保留原时间点，不再因处理器的状态切换制造位移；已核对步行窗口的移动点与参考距离保持原结果。回放并非测绘真值，不能据此宣称所有原始误差都已消除。公开回归样本仅使用合成数据。

## 安装与限制

验证：256 项 Node 测试、131 项 JVM 回归检查通过。独立 Android 模拟器先用实际 1.9.7 重现断采后的虚假停留跳移，再同签名覆盖安装 1.9.8；26 项状态／数据保留／真实 WebView／传感器恢复检查及 55 项地图回归检查通过。覆盖安装核对记录、设置、Wiki 和聊天不变；每条原始定位及原始 GPX、D 对照 GPX 完全一致。APK 的 33 个应用资产与源码逐字节一致。测试未使用私人 Key 或小米实体机。

直接覆盖安装同签名 APK，不要先卸载。历史记录在打开轨迹页时重算，原始数据保留。已采集数据不能补出缺失的真实走法；无采样的区域继续明确为推断虚线。小米后台和真实传感器的改善仍需新版本在实体手机上的后续采样反馈，模拟器不能验证高楼多径或厂商省电行为。
