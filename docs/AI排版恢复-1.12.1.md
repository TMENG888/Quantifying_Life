# AI 排版恢复修复 1.12.1

## 修复范围

- 排版错误直接显示在编辑器内部，保留明确的「重试排版」入口；不会被模态弹窗遮住，也不会在请求结束时自动清空错误。
- 原文、草稿和正式记录分离。生成失败、未采用预览或后台返回晚于用户修改时，不覆盖正文；采用后仍可撤销，点击保存才更新正式记录。
- 空响应、输出截断、JSON/结构校验错误，每一批最多额外重试一次；断网、认证失败和额度/限流错误不自动重试。多批长文不会因单批失败而展示不完整预览。
- 若模型返回的排版与原文完全一致，明确提示「未生成新的排版」，不冒充成功。
- 百炼根据官方域名识别，包括工作空间的 maas.aliyuncs.com 域名。Chat 协议使用 enable_thinking 控制推理；关闭推理时不会仅因 profile.id 为 custom 而遗漏参数。其他服务不发送百炼专用开关。
- 排版请求的输出上限为 8192；非推理排版指定 plan_record_layout 工具。其他普通请求仍为 4096。截断结果不当作完整工具参数采用。
- 保护粒度缩小到内联加粗、链接、行内代码等原始片段，周围文字仍能分段。图片独立保护，已有标题/块级列表/整块代码及不平衡的复杂 Markdown 仍保守保留。不允许在原有格式内重复套加粗。
- 列表一个 block 的多个相邻 ID 合成一个完整条目；原文明示的连续编号步骤可拆为对应条目，复用编号，避免每个逗号分句都变成一项或出现「1. 1.」。不会把普通叙事推断为步骤。

正文仍从原始片段组装，不采用模型自由改写的正文；原有顺序、人物数字、限定条件及观点保留。普通新段末逗号可改为句号，编号的列表标记可规范化。排版不等于事实核验。

## 验证结果

测试环境为 Android 11 模拟器及 WebView 83；不是用户的小米真机。正文按截图转录，字数计数为 193 字，未读取手机私人数据库。

- Node 自动化：291 项通过，其中排版测试 12 项，覆盖内联保护、图片、完整步骤、乱序/遗漏拒绝和有限重试。
- LayoutRecoveryTest：42 项通过，覆盖安卓弹窗内错误可见性、手动恢复、最多两次调用、认证/网络不自动重试、原文保护，以及本机 HTTP 原生响应解析与域名识别。该组为明确标注的合成故障/本机服务，不冒充真实模型。
- LayoutLiveTest：26 项通过，使用 App 原生 HTTP 调用已有百炼配置的 deepseek-v4.1-flash。两组相同原文、一组已有加粗，最终均出现可采用预览和五个完整列表项；采用与撤销通过。三组实际产生 4 次请求：第二组首次结构未通过严格校验，自动重试后成功。
- 真实端到端耗时分别约 3.0、7.5、6.8 秒（第二组含重试）；返回 usage 均无推理 token。少量实测不构成长期成功率或耗时保证。
- LayoutFlowTest：30 项通过，包含历史长文、行段距、分页、预览/采用/撤销/重做、并发编辑保护及长文分批。
- ReaderSaveTest：71 项通过；ReaderSaveSafetyTest：9 项通过；ImageSpacingTest：19 项通过。

版本为 1.12.1 / code 53，使用既有签名，不更换包名，不新增数据库迁移。测试用临时明文凭据在验证后清理，安装包不包含测试 Key。

## 使用

覆盖安装后，在笔记「更多 → AI 排版」中重试；先查看预览，再选择「采用排版」，最后点勾保存。若服务仍异常，编辑器将保留原因和手动重试入口，正文不变。
