# 知时 1.16.0：主题标签与使用反馈

## 使用方法

- 记录 → 学习／工作／随笔 → 主题统计：按日期、篇数、时长查看主题排行，点主题查看对应记录。
- 编辑记录 → 标签与信息：输入新标签、选择常用标签或移除标签。AI 原有标题／标签补全仍可使用，本轮不自动付费回填历史标签。
- 统计 → 使用反馈：查看页面进入、活跃停留、操作计数、关键请求成功／失败及常见路径，可复制聚合反馈用于后续优化。

## 统计口径

- 经验与灵感统一为随笔入口，底层 idea／experience、原文及时间不迁移、不丢弃。
- 一条记录归属多个标签，每个主题计完整篇数与时长；不同主题不可相加。上方总量按记录计算一次，无标签归入未分类。
- 标签按空格、全半角和英文大小写去重；不自动把语义相近标签合并，不改写历史标签。
- 学习缺失／零时长只计篇数，不从文字长度估计时长；篇数是学习条目数，不是去重作品数。
- 工作日志统计篇数，工作班次按自身标签统计净工时；班次扣休息、按日期边界截取，进行中截至当前刷新。日志不继承当天班次时间。标签未设置的班次计入未分类。
- 随笔统计条数和记录天数，不虚构时长。排行与记录明细分页，避免长页失控。

## 本机交互统计与隐私

- 原始生活记录与功能使用统计独立。仅存按日聚合的预定义页面、事件、结果、相邻路径计数，无逐次点击日志、持久用户／设备ID、输入内容、坐标、文件名、Key或账号。
- 使用 WebView 本机存储，覆盖升级保留；清应用数据或卸载会清除，不随普通生活记录备份导出。
- 默认启用，最长180天，可暂停、清空。复制反馈仅含聚合数据及规则建议；用户自行发送，不联网、不调用模型。
- 前台活跃时间按最近交互后60秒窗口统计，后台不计。长时间阅读可能少计，不能当作真实注意力或学习时长。超过30分钟无交互视为新会话。
- 操作点击与返回结果不是严格漏斗；配图提交成功不代表图像生成完成。学习保存来源按记录 source 字段，不等于新增篇数，编辑已有记录也计保存。
- 建议须先达到7个活跃日、10次会话。对高失败率优先提示可靠性修复；低频入口可考虑折叠，而不是自动删除备用功能。建议不改动任何功能。

## 实现

`topic-stats.js` 为可独立测试的标签／统计层，使用现有精确工时算法；`topic-insights.js` 实现排行与下钻；`usage-telemetry.js` 为无网络依赖的本机汇总；`usage-insights.js` 展示反馈与清理／复制控制。

设计沿用绿色与暖纸色，不增加底部模块；采用直接标注数值的横向排行，不用会误导多标签加总的饼图。
