# 聊天滚动修复 1.12.3

## 原因与修复

旧版发送后会重建聊天 DOM。旧聊天容器的延迟 scroll 事件仍可能触发，原处理器却通过 ID 读取新容器的初始位置 0，错误覆盖「跟随最新消息」状态，导致发送和回复后都停在历史开头。消息本身没有被置顶或乱序。

本版做了以下修复：

- 只处理当前且仍连接在页面上的聊天容器事件，忽略旧容器事件。
- 新容器完成布局前不把其初始位置当作用户阅读位置；连续重绘也保留原滚动状态。
- 丢弃失效的布局恢复回调，避免旧容器或旧会话操作当前界面。
- 发送时跟随最新消息，回复时继续跟随；等待回复期间手动浏览历史则保留阅读位置，提供「↓」回到最新对话。
- 键盘展开/收起时仅在原本跟随底部的情况下继续跟随，不强制打断历史阅读。

不修改消息入库顺序、模型配置、知识库或生活记录数据库结构。

- Node：301 项通过，新增 6 项滚动回归覆盖旧容器事件、回复跟随、历史阅读、同帧连续重绘、键盘尺寸变化和草稿保留。
- ChatScrollTest：31 项通过。覆盖空会话、20 条历史下短/长回复、从旧历史发送、键盘展开/收起、附件、等待期间上翻历史、回到底部保留草稿、网络错误回复。
- 旧版相同历史短回复场景：发送后 scrollTop=0，距底部约 3780 CSS px；回复后仍为 0，距底部约 3869 CSS px。新版发送/回复后距底部小于 1 CSS px（计算误差）。
- LayoutReliabilityTest 18 项、LayoutFlowTest 30 项、ReaderSaveSafetyTest 9 项回归通过。
- 已查看发送、回复及键盘截图；沿用原绿色与暖色背景，无 UI 配色更改。
