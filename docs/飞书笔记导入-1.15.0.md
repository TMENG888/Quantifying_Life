# 飞书笔记导入 · 1.15.0

## 手机怎么用

1. 在飞书复制一篇新版文档或知识库文档的链接。
2. 把链接直接发到知时 AI 助手，或说「导入这篇学习笔记 + 链接」。也可在对话右上角选项点「导入飞书笔记」。
3. 核对标题与原文预览，设置学习日期、分钟数（默认 0，不根据篇幅猜时长）。
4. 若有分栏或未支持的内容，核对提示后勾选确认，点「导入学习记录」。成功后进入这条记录的阅读模式。

这一步不需要聊天模型 Key、不调用模型改写正文，也不会更改飞书原文。知时只在用户确认后写入自己的本地学习记录；之后沿用现有 Wiki 自动整理及历史问答机制。Wiki 整理仍按原设置调用模型，相关记录可能进入模型上下文。

## 再次导入与更新

- 文档编号用于全局查重，分享参数不同、学习日期不同，都不会绕过同源检查。
- 再发原链接，或编辑记录时在「更多」点「检查飞书原文更新」。本地有未提交编辑时需先保存。
- 内容未变时直接查看本地，不新增一条。
- 飞书变更、本地正文未改动：确认后替换标题、正文和图片，保留本地学习日期、分钟数、标签及其他元数据。
- 本地标题、正文或图片已修改，或原有记录还未建立导入基线：拒绝自动覆盖，可以保留本地或另存一份飞书副本。副本仍保留原文链接，不参与同源自动更新。
- 保存按当前版本在数据库事务内执行。记录同时被修改时拒绝覆盖；同一预览因回复丢失而重试，不会重复创建记录或副本。

不是持续后台同步或双向同步；在飞书修改后，需要重新发送链接或手动检查更新。

## 权限、网络与边界

- 公开页面直接通过 HTTPS 读取，兼容飞书的多次跳转与匿名会话 Cookie。
- 需要登录时可打开独立飞书阅读页，在手机上登录并拥有阅读权限后，等待完整文档加载，点「读取此文档」。阅读页没有知时原生桥接；登录信息不存入笔记、不发给模型，不借用电脑登录态，不绕过权限。企业 SSO、复杂登录或新版页面结构可能仍无法读取。
- 读取失败显示原因及重试入口，不创建空记录。取消不写入数据库；已经读取的预览在本机暂存，可于重开 App 时恢复。
- 仅支持 `/docx/`、`/wiki/` 文档，不支持旧版 `/docs/`、多维表格、妙搭应用或整库递归导入。
- 按结构块还原正文、标题、列表、代码、常见行内格式及引用。分栏按顺序转为单列；不能保证复杂表格、画板、附件、嵌入组件的完整呈现，会明确标注，不冒充已成功导入。
- 分页、缺失内容块或不能识别的文本结构直接停止，不将残缺正文静默视为全文。
- 单次最多 20000 个内容块、100 万正文字符、100 张图片；页面最多 12MB，单张原始图片 20MB，下载图片累计约 64MB，超出需拆分。并非单条笔记的通用字数限制。
- 支持的图片下载到本机后沿用知时图片处理与备份机制；无法取得的图片显示占位和警告，需确认后才可保存。含图片文档建议逐项核对。
- 正文中的网页指令仅作为文档内容，不执行；不自动读取正文的任意外部地址。公开读取及图片下载拒绝内网地址与非允许域名，逐跳检查重定向，不输出 Cookie 或密钥。

## 验证

测试数据：用户提供的公开《Scrapy项目框架》《LangChain框架入门概念》，以及人工合成的长正文、冲突记录、图片、错误页面。第二篇遍历了 53 个正文块，16 个代码块与独立飞书读取结果逐一核对一致，首尾正文均保留，第二篇导入未修改第一篇。画板以明确占位和警告呈现，需用户接受限制后才保存。

真实文档没有普通正文图片；本轮不能据此承诺所有飞书图片或私有企业文档已通过实机验证。个人文档链接通过测试运行参数传入，原文只保留在本机测试目录和测试机，不作为仓库固定样本或打进发布 APK。

详细结果及 APK 校验值记录在交付目录的测试报告中。未使用真实模型 Key，也未修改用户的飞书文档。
